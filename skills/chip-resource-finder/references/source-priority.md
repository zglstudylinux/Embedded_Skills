# 来源优先级与证据规则

判断哪些链接可信、如何标注来源时，使用这些规则。

## 来源等级

| 等级 | 来源 | 用途 |
|---|---|---|
| 官方一手 | 厂商产品页、文档中心、SDK 门户、官方 GitHub/Gitee、评估板页面、工具页面 | 核心文档和下载的默认来源 |
| 官方生态 | ARM/CMSIS pack 索引、Keil pack、IAR、SEGGER/J-Link、OpenOCD、PlatformIO 官方平台 | 工具链和调试支持 |
| 授权伙伴 | 评估板厂商、模组厂商、分销商、参考设计伙伴 | 仅当官方一手来源不完整时使用 |
| 社区 | 个人 GitHub 仓库、博客、论坛、教程、镜像 | 仅作补充；必须明确标注 |
| 高危 | 随手转载的 PDF 镜像、SEO 下载站、无版本号的网盘链接、爬虫抓取的数据手册数据库 | 避免作为主要证据 |

## 默认策略

- 官方一手线索不缺失、不完整时，始终优先官方一手来源。
- 不要为了提高覆盖率而主动打开补充性来源。
- 优先产品页/文档页，而不是裸 PDF 镜像。
- 优先官方仓库的 releases/tags，而不是转载的压缩包。
- `备注`中只记录当下肉眼可见的版本、发布、生命周期或需登录等细节。
- 元数据不清晰时直接省略，而不是继续深挖。

## 搜索查询模式

最多从三组查询开始：

- 产品页：`<chip model> official product page`
- 文档：`<chip model> datasheet reference manual errata`
- SDK/工具：`<chip family> SDK examples programming tool`

仅当缺失必备条目时才补充定向查询，例如硬件设计指南、bootloader、ISP、应用笔记、SVD、CAD 或评估板原理图。

## 危险信号

- 文档标题指向另一颗芯片或另一个系列。
- 下载页缺少厂商品牌或官方归属标识。
- SDK 例程针对的开发板并不使用用户询问的芯片。
- 封装后缀意味着存储/封装/温度差异，而找到的文档并未覆盖。
- 社区的权宜做法没有对应的勘误表或厂商说明支撑。
