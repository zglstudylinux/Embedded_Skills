# 芯片资源检索（Chip Resource Finder）

使用此 skill 把一个芯片型号转化为一份精炼的嵌入式开发资源报告。主要交付物是一个 HTML 文件，帮助用户快速找到硬件设计、软件开发、烧录编程和量产环节所需的资源。

## 必须遵守的行为

- 只要用户需要芯片文档、SDK、例程、工具或下载页面，就必须实时联网获取当前有效的链接。
- 优先使用官方一手来源：芯片厂商产品页、文档中心、官方 SDK 门户、官方 GitHub/Gitee 组织、官方评估板页面、官方工具页面。
- 厂商为中国大陆企业时，优先使用中文官网、中文文档中心和国内下载页；海外厂商优先使用全球官网。
- 仅当官方来源缺失或不完整时，才使用合作伙伴、分销商、开发板厂商、社区、博客、镜像或网盘来源，并明确标注。
- 不得编造链接、文档版本、SDK 版本、工具支持、仓库归属或适用性。
- 区分确切订货型号与系列级文档。很多 MCU 资源是系列级的。
- 保持工作流轻量。除非用户明确要求，不做反复探测、批量 HEAD 检查或深度下载验证。

## 工作流

1. 解析芯片身份。
   - 提取厂商、系列、确切型号、封装/后缀、存储变体、无线/模组变体，并判断输入是否可能是板卡名。
   - 归一化常见别名，但在回答中保留用户的原始型号。

2. 优先检索官方来源。
   - 从三组查询开始：产品页、文档中心、SDK/工具页。
   - 先搜确切型号，再搜系列。
   - 仅当第一轮遗漏重要资源时，才补充类别专属查询。

3. 对找到的资源分类。
   - 决定各表格收录内容时阅读 `references/resource-checklist.md`。
   - 使用三个输出表：硬件开发、软件开发、烧录编程/量产测试。
   - 一份资源只有在确实承担多重角色时，才可以出现在多个表格中。

4. 核查来源质量。
   - 判断来源可信度时阅读 `references/source-priority.md`。
   - 优先使用稳定的产品/文档页，而不是随手转载的 PDF 镜像。
   - 优先使用官方仓库的 releases/tags，而不是转载的 ZIP 包。
   - 把过期、需登录、已归档、区域限定或系列不匹配的资源在`备注`中标记。
   - 官方一手线索完整即停止，不继续深挖。

5. 产出精炼的资源包。
   - 以芯片身份识别和假设条件开头。
   - 生成 HTML 报告文件，包含下文要求的三个中文表格。
   - 除非用户指定其他路径，文件保存在当前工作区，使用稳定的小写文件名，如 `chip-resource-<normalized-chip-model>.html`。
   - 对话回复只给简短总结和生成的 HTML 文件的可点击链接。
   - 包含最小下载集和建议阅读顺序。
   - 列出缺失或有风险的条目，不过度展开。

## HTML 输出

生成独立的 HTML 文件。直接用浏览器打开即可阅读，无需开发服务器。

必需的 HTML 章节：

- 芯片识别
- 硬件开发资料
- 软件开发资料
- 烧录编程 / 量产测试资料
- 最小下载集
- 推荐阅读顺序
- 缺失或风险项
- 检索证据

使用简洁的语义化 HTML：

- `<h1>` 作为芯片资源报告标题。
- 每个章节用 `<section>`。
- 三张资源表用 `<table>`。
- 链接用 `<a href="...">`。
- 用一小段 `<style>` 实现清晰的排版、表格边框、间距和打印友好布局。

不要添加外部 CSS、JavaScript、跟踪代码或装饰性资源。

## HTML 视觉风格

采用受 shadcn/ui、GitHub Primer 和 Tailwind UI 文档表格启发的简洁技术仪表盘风格：

- 页面背景为白色或极浅灰。
- 主容器居中，最大宽度约 `1120px`。
- 紧凑页眉：左侧芯片名/报告标题，右侧生成日期与来源策略。
- 芯片身份用 3-4 张紧凑摘要卡片展示。
- 三个资源章节使用一致的表格结构。
- 每张表格上方加一句简短说明。
- 使用细腻的边框、浅灰表头、舒适的单元格内边距，可选行悬停高亮。
- 使用小号优先级徽章：`必需`、`推荐`、`可选`。
- 建议徽章色调：必需 = 暗红、推荐 = 暗蓝、可选 = 灰色。
- 风险/缺失项用浅黄色提示块。
- 检索证据用浅灰色信息块。
- 页面应呈现专业工程资源包的质感，而不是营销落地页。
- 保持打印友好：不用深色主题、不用大面积装饰背景、不引用外部字体或图片。

表格结构：

| 优先级 | 类别 | 资料 | 来源 | 链接 | 备注 |
|---|---|---|---|---|---|

硬件、软件、烧录/量产三张表格使用相同结构。

## 类别指引

- MCU/SoC：如果存在参考手册、SDK、勘误表、例程和编程工具，不要只停在 datasheet。
- 外部外围芯片：优先 datasheet、应用笔记、寄存器表、命令集、时序、参考驱动和评估板文件。
- 无线芯片/模组：官方提供时，收录射频设计指南、天线/layout 指南、认证说明、固件协议栈、主机接口协议和产测/校准文档。
- 电源/模拟/接口芯片：收录设计指南、评估板文件、layout 要点、热数据、参考原理图；仅当该器件需要固件交互时才收录软件资料。
