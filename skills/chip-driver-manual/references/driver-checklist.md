# 驱动检查清单

生成、审查或调试嵌入式外设驱动前，使用此清单。

## Bring-Up 前置条件

- 确认芯片料号和封装变体。
- 确认外设实例和基地址。
- 确认总线时钟域和时钟门控。
- 确认复位控制和必要的释放复位顺序。
- 确认电源域或模拟域要求。
- 确认 pinmux 功能、引脚电气模式、上拉/下拉、驱动强度和输入使能。
- 确认 IRQ 号、中断控制器名称、优先级模型和标志清除方法。
- 使用 DMA 时，确认 DMA request ID、通道、握手方向和 FIFO 行为。

## 寄存器安全

- 除非手册规定，否则不要写保留位。
- read-modify-write 时，为保留字段保持复位值。
- 将 W1C 字段与普通 RMW 更新分开处理。
- 将 read-to-clear 状态字段视为破坏性读取。
- 避免读取 write-only 寄存器。
- 不要在未检查 busy、ready 或 sync 标志的情况下假设写入已完成。
- 确认自清除位和超时行为。
- 确认 lock/unlock key 或受保护寄存器序列。

## 初始化序列

- 除非手册另有说明，触碰外设寄存器前先使能必要时钟。
- 仅在完成必要时钟或电源设置后释放复位。
- 当毛刺风险重要时，在使能外部信号输出前配置 pinmux。
- 使能外设前先编程 baud/rate/timing 字段。
- 使能中断前清除陈旧状态标志。
- 仅在阈值和地址配置完成后启用 FIFO/DMA。
- 除非手册要求分阶段使能，否则最后再使能外设。
- 按文档轮询 ready/busy 标志或插入必要延迟。

## 审查问题

- 每个 magic number 是否映射到已记录的寄存器字段或枚举？
- 时钟频率和分频器是否来自已确认的输入时钟？
- 中断清除方式是否符合已记录的标志类型？
- 是否处理错误标志，而不只是 data-ready 标志？
- 硬件等待是否有超时循环？
- 代码是否支持多个实例，且不混淆基地址、时钟或 IRQ？
- volatile MMIO 访问和 barrier 是否适合目标平台？
